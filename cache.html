Prompt Cache 實驗

左邊調整「下一次請求」，右邊逐塊比對它和快取裡存的前綴：從頭開始一路相同才能重用，第一個不同的地方就是快取斷掉的位置，後面全部作廢。頁面已經先送過一次請求，你送出第二次就能看到命中或失效的原因。

工具（中途增減會怎樣？）
快取按模型分開，換模型就用不到上次的快取。
快取存活時間（TTL）
TTL 是寫入快取時決定的；之後每次命中都會重新計時。
cache_control 斷點位置
斷點之前（含）的整段前綴會被快取，前綴至少要 1,024 tokens 才會快取。

所有數字都是示意估算：token 依字數粗估，價格用示意單價（輸入 $3、輸出 $15、快取寫入 1.25 倍＝$3.75、快取讀取 0.1 倍＝$0.30，每百萬 token；1 小時 TTL 的寫入示意為 2 倍＝$6）。實際欄位與計價請以官方文件為準。

看完要記得

    
    
      
  • 穩定的放前面、會變的放後面。快取比的是前綴：順序是 tools → system → messages，只要前面有一個字不同，後面全部作廢。
    • 
      
  • 不要在 system 放時間戳記。每次都不同，等於每次都在第一個區塊就斷掉；要給時間就放在最後一則訊息裡。
    • 
      
  • 對話中途不要增減工具。工具定義在最前面，多一個少一個，後面的 system 和歷史都連帶失效。
    • 
      
  • 命中會重新計時。只要在 TTL 內持續有請求，快取就一直活著；中斷超過 TTL 才會過期，需要重新付寫入的價錢。
    • 
      
  • 快取讀取只要輸入價的約 0.1 倍，寫入約 1.25 倍：前綴要夠長（至少 1,024 tokens）、而且會被重複用，才划算。
