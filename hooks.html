看完要記得

    
    
      
  • Hook 是確定性的，不靠記憶：事件發生就執行，模型有沒有記得規則都不影響。

  • PreToolUse 可以擋，PostToolUse 適合自動檢查：工具跑完才擋已經來不及，只能回報或修正。
    • 
      
  • matcher 決定套用範圍：Bash、Edit|Write、mcp__.* 是用工具名稱比對的正規表示式；範圍太寬會拖慢每個動作。
    • 
      
  • Hook 本身是會執行的指令：它有你的權限，來路不明的 hook 設定和來路不明的腳本一樣危險，要審過再放進 repo。

口試怎麼答（約 30 秒）
Hook 就是 Claude Code 在生命週期事件點自動執行的 shell 指令，用來把規則變成確定性的強制，而不是靠模型記得。例如我會在 PreToolUse 掛一個 hook，偵測到 rm -rf 或 git push --force 就 exit 2 擋下，並把原因回給模型；在 PostToolUse 對改過的 .cs 檔自動跑 dotnet format。CLAUDE.md 只是提示，長對話壓縮後可能被忘掉，hook 每次都會跑。
  • 被追問時可以補：matcher 是比對工具名稱的正規表示式，像 Edit|Write 或 mcp__.*，決定 hook 套用到哪些工具。
  • 被追問時可以補：hook 透過 stdin 收到 JSON（tool_name、tool_input 等），用 exit code 表達決定；細節要以官方文件為準。
  • 被追問時可以補：Hook 是會在本機執行的指令，要像程式碼一樣審查，不要直接信任別人給的設定。
